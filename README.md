# Зал, где слышно друг друга + Table Mode

MVP для живого демо на хакатоне: два продукта для одного ресторана в одном Next.js-приложении и одной базе Supabase.

| Модуль | Что делает |
| --- | --- |
| **Зал, где слышно друг друга** | Ресторан на 200 мест разбит на акустические зоны: **A «Поговорить»** 60–65 дБ, **B «Фон»** 65–72 дБ, **C «Движ»** у бара 72–80 дБ. Телефоны меряют шум, алгоритм держит целевой уровень, управляя громкостью и темпом музыки в каждой зоне. |
| **Table Mode** | Игровой слой для стола: компания сканирует QR, попадает в общую комнату и играет «эпизод» сезона своей компании. Прогресс и очки сохраняются по 4-символьному коду. Телефон — пульт, а не экран. |

**Как модули связаны.** QR на столе ведёт в Table Mode, а в шапке игры есть кнопка «🔊 Громко?» — она сразу убавляет музыку зоны этого стола. В итоге эпизода гостя спрашивают «Было слышно друг друга?» — ответ попадает в метрики дашборда зала. Бронь подбирает стол по атмосфере, а QR этого стола открывает игру.

---

## Быстрый старт (за минуту, без Supabase)

```bash
npm install
npm run dev
# откройте http://localhost:3000
```

Без переменных Supabase включается **локальный режим**: данные в памяти Next.js-сервера (+ файл `.data/local-db.json`), realtime через SSE, сид загружается автоматически. Без `ANTHROPIC_API_KEY` Table Mode играет на готовой библиотеке и шаблонном итоге. Всё работает офлайн — это запасной план для зала без интернета.

> Микрофон в браузере работает только по HTTPS (или на `localhost`). Для телефона-датчика используйте деплой на Vercel (см. ниже) или `npm run dev:https` в локальной сети: Next.js выпустит самоподписанный сертификат, телефон открывает `https://<IP ноутбука>:3000/sensor?zone=A` и один раз подтверждает предупреждение о сертификате.

## Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor** → вставьте и выполните [`supabase/migrations/20261003000000_init.sql`](supabase/migrations/20261003000000_init.sql), затем [`supabase/seed.sql`](supabase/seed.sql). Оба файла идемпотентны.
   - Или через CLI: `npx supabase link --project-ref <ref> && npx supabase db push` и затем выполнить `seed.sql`.
3. **Project Settings → API**: скопируйте URL, `anon` и `service_role` ключи в `.env.local` (шаблон — [`.env.example`](.env.example)).
4. Realtime включать вручную не нужно: миграция сама добавляет таблицы `zones`, `readings`, `events`, `feedback`, `rooms` в публикацию `supabase_realtime`.

**Модель доступа.** Браузер получает только `anon`-ключ и может лишь *читать* таблицы для realtime (`zones`, `readings`, `events`, `feedback`, `rooms`, `hall_tables`). Брони, компании, участники, эпизоды, ответы, секретные миссии и библиотека закрыты RLS; все записи идут через API приложения с `service_role`. Показания хранятся 24 часа (pg_cron, если доступен; иначе чистит `/api/control`).

Локальный Supabase для разработки: `npx supabase start` (нужен Docker) — миграция и сид применятся сами, ключи покажет `npx supabase status`.

## Деплой на Vercel

1. Импортируйте репозиторий в Vercel (фреймворк определится сам).
2. Добавьте переменные из `.env.example`: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_PIN`, при желании `ANTHROPIC_API_KEY`.
3. Deploy. HTTPS даёт сам Vercel — микрофон на телефонах заработает.

На Vercel нужен Supabase: у каждой серверной функции своя память, поэтому локальный режим там не синхронизирует устройства (главная и `/api/health` предупредят об этом). `NEXT_PUBLIC_*` встраиваются при сборке — после их изменения сделайте Redeploy.

## Сценарий питча

**Зал (`/demo/hall`)**
1. Ноутбук: открыть `/demo/hall`, нажать «Включить музыку зоны» (браузеру нужен один клик для звука).
2. Телефон: отсканировать QR на экране → `/sensor?zone=A&t=7` → «Запустить датчик». Положить телефон на стол рядом с ноутбуком.
3. Громко поговорить. Через 15–30 секунд медиана за 30 с перевалит за цель + 3 дБ: в ленте появится «21:15 · Зона A 74 дБ → музыка −10%», плеер плавно стихнет. Если громко дольше 2 минут — ещё −10% и темп медленнее. Если шум не уходит, алгоритм перестаёт убавлять музыку и пишет менеджеру «шумит одна компания — предложите пересадку».
4. «Громко?» с телефона (`/table?zone=A&t=7` или кнопка в Table Mode) — музыка тише сразу, событие видно в ленте.
5. «📅 Волна броней через 20 мин» — алгоритм заранее убавит стартовую громкость.
6. **Нет телефона или сети?** «🗣 Имитировать шумную компанию» шлёт синтетические показания, а **«Симуляция пятницы 20:00–23:00»** целиком работает в браузере: 3 часа за 60 секунд, два графика — «без системы» (музыку прибавляют «на глаз», зона A уходит в красное) и «с системой» (зона A держится в цели, зона C громкая в своём диапазоне).

**Table Mode (`/demo/table`)**
1. «Начать демо» — четыре «телефона» садятся за стол 7, Аня ведущая.
2. В окне Ани: «Новая компания» → название → повод → длина. Остальные видят лобби в реальном времени.
3. Играйте в окнах или жмите «🤖 Симулировать голоса»: разогрев, секретные миссии (шторка — потянуть вверх), финал с угадыванием, фраза вечера, итог с конфетти.
4. На итоге — код компании. «Новая игра» → «Продолжить сезон» → код: второй эпизод видит очки и итог первого.
5. `/admin` (PIN по умолчанию `1234`) — активные столы, библиотека, «Сгенерировать 20 новых», метрика возврата.

## Как работает алгоритм (`/api/control`)

Чистая функция [`decide()`](src/lib/acoustic/control.ts) — та же в реальном времени и в симуляции; покрыта тестами.

- Для каждой зоны в авторежиме — **медиана дБ за 30 секунд** по всем датчикам зоны.
- **Выше цели + 3 дБ** → громкость −10% (минимум 0.15); держится **больше 2 минут** → темп на ступень медленнее.
- **Ниже цели** → громкость +5% (слишком тихо — слышны соседи); долго тихо — темп на ступень быстрее (не выше «родного» для зоны).
- **Гистерезис**: «громко» снимается только ниже цели + 1 дБ, «тихо» — выше цели + 2 дБ; **пауза 60 секунд** между изменениями.
- **«Шум гостей»** = измеренный уровень минус вклад музыки (энергетическое вычитание). Вклад музыки оценивается по текущей громкости и калибровке «пустой зал» (кнопка в карточке зоны).
- **«Предложите пересадку»** вместо бесконечного снижения: если один датчик (стол) громче остальных на 6+ дБ, или гости громче музыки на 6+ дБ, а музыка уже на минимуме / убавлена 3 раза за 10 минут без эффекта.
- **Прогноз**: если в ближайшие 30 минут в зону придут брони на `FORECAST_GUESTS`+ гостей (по умолчанию 16) — заранее −10%.
- **Алерты**: зона выше цели больше 5 минут; 3+ нажатия «Громко?» за 10 минут.
- Каждое решение пишется в `events`; несколько открытых дашбордов не принимают решение дважды (оптимистичная блокировка по `version`).

## Приватность

Звук никогда не записывается, не сохраняется и не отправляется. Телефон держит сэмплы только в буфере `AnalyserNode` и сразу сворачивает их в одно число — средний квадрат → dBFS → + калибровочный оффсет. Раз в 2 секунды на сервер уходит только это число (`{ zone, sensor_id, db }`). Это крупно написано на странице датчика.

## Table Mode

- **Вход** `/t/[table]`: имя → «Войти». Первый вошедший — ведущий: «Новая компания» или «Продолжить сезон» (код), повод (просто встреча / день рождения / кто-то вернулся / отмечаем успех), герой вечера, длина: **короткий** (разогрев → миссии → финал) или **полный** (+ «Второй круг» и «Про повод»).
- **Разогрев**: «Кто из нас…» — каждый голосует за имя; когда проголосовали все, сам открывается результат и плашка «Обсудите вслух, почему».
- **Секретные миссии**: у каждого своя, под шторкой; одна на стол — с персоналом. Текст миссии получает только её владелец (по секретному ключу игрока), в общем состоянии комнаты его нет.
- **Финал** (лучше всего — за десертом): остальные угадывают миссию из 4 вариантов. Выполнил незаметно — **+3**, угадал чужую — **+1**. Затем фраза вечера и голосование за лучшую.
- **Итог**: MVP, фраза вечера, тёплый итог от AI с отсылкой к прошлым эпизодам, таблица сезона, код компании крупно, «Отправить итог в чат» (Telegram / WhatsApp), тизер следующего эпизода, вопрос «Было слышно друг друга?».
- **Надёжность**: игрок хранится в `localStorage` — перезагрузка не выкидывает; ведущий молчит 2 минуты — ведущим становится следующий (или «Стать ведущим» через 30 с); комната сбрасывается после итога («Новая игра» или через 45 минут) и через 4 часа неактивности. Одновременные действия не теряются (версия комнаты + повтор).

### AI

Только на сервере (`ANTHROPIC_API_KEY`), модель — актуальный **Claude Sonnet** (`claude-sonnet-5-5`, можно поменять через `ANTHROPIC_MODEL`). Ответы — строгий JSON по zod-схеме (structured outputs), плюс серверный фолбэк на случай отказа модели.

- **Эпизод**: берёт одобренные элементы и адаптирует их под повод и имена (на день рождения — вопросы про именинника). Не придумывает новое с нуля во время игры; адаптация идёт в фоне — эпизод можно начинать сразу.
- **Итог эпизода**: имена, очки, фразы вечера, итоги прошлых эпизодов → 2–3 тёплых предложения.
- **Библиотека**: «Сгенерировать 20 новых» → на модерацию (`approved=false`) → «Одобрить / Удалить».
- Жёсткий system prompt (только добрый юмор; без политики, религии, интимного, алкогольных челленджей, насмешек над внешностью, деньгами и отношениями) и второй фильтр по стоп-словам.
- **Fallback**: нет ключа, сбой, отказ или таймаут → сид и шаблонный итог. Демо не ломается из-за AI.

## Ограничения MVP

- Телефонный микрофон — не шумомер: без калибровки оценка может отличаться на ±5–10 дБ (поле «Калибровка» на странице датчика решает это за минуту).
- Взвешивание A не применяется — меряется полный уровень (RMS → dBFS).
- Вклад музыки оценивается по модели громкости, а не измеряется отдельно; калибровка «пустой зал» делает оценку точнее.
- Админка защищена простым PIN — для продакшена нужна нормальная авторизация.
